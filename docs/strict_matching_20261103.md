# 全条件机理匹配与正常报告

## 判定逻辑

同一时刻，同一条规则的全部条件满足，才判为对应故障。任意条件明确不满足，该条规则判为正常；没有不满足项但有缺值、无效比值等未知项时，判为无法判定。未知不作为不满足。空规则配置不允许保存。

例如四项条件：四项满足为故障；三项满足、一项不满足为正常；三项满足、一项未知为无法判定；两项满足、一项不满足、一项未知，该条规则仍为正常。

不同故障规则分别判断，任一规则全部满足即判为对应故障，另一条规则正常不能抵消它。没有命中故障时，全部适用规则正常才能给出总体正常；存在未完成的适用规则或来源配置阻断时，总体无法判定。

全部历史按同一时间对齐，不能将不同时刻的条件拼接。最近记录决定当前状态；历史曾全部满足的故障单独说明，历史不改变最近判定。满足率仅保留供核查，不生成部分符合、疑似、支持等级、概率或严重程度。

## 正常报告

采用当前状态、简洁说明、日常维护建议的写法。摘要明确“当前设备状态正常（本次机理规则判定范围内）”，解释未触发完整故障机理。建议保持例行点检、润滑、紧固和监测，不安排未命中故障的动平衡、拆检或更换。

不照搬示例中健康状态良好、温度或转速稳定、波形未见冲击等未经本次数据支持的表述。全部历史均正常时可说明历史未触发故障；有历史故障或无法判定时分别说明。

只有最近或历史全部满足的故障方向进入图表选择；无故障方向的正常报告不插入无关图。台账、工况记录占比、原始数据、完整规则明细及来源追溯保留，Word和PDF继续沿用既有模板。

## 使用与核查

重新上传案例或使用已导入案例生成新报告后生效；历史报告不追改。网页“核查资料”和逐时刻CSV可查看各条件及该规则判定。正常、故障、无法判定均由程序计算，大模型只解释结果、给出建议并返回实际知识引用。

规则仍从独立入口维护，知识DOCX不自动执行。所有历史仍按用户指定共用最新频谱，客户最终值不复算。提示词以 report_writer_prompt.md 为准。代码测试覆盖全满足、明确不满足、缺值、来源阻断、不同规则冲突、历史故障及正常写作边界。
