# 真实案例输入与机理匹配

## 使用

项目位于服务器 /data1/tjb/projects/device-report-demo；本机通过SSH转发访问 http://127.0.0.1:18046/。

上传现有真实案例ZIP，导入并检查后生成报告。勾选大模型时使用服务器已配置的接口撰写解释与建议；不勾选也会完成相同的全部机理规则计算。原模拟样例不恢复。

## 输入

沿用schema_version为1.1、data_type为real_measurement的case.json及data目录CSV，不需要补充运行状态、运行方向、负载或工况才能判定。文件校验值、单位、设备测点和坐标仍检查。客户最终特征值不复算，不执行FFT、积分、特征提取或插值。

CSV表头为source_row,x,y，保留时间、原值文本和来源行号。支持七类历史指标：velocity_rms（mm/s），acceleration_rms、acceleration_peak、low_frequency_impulse（m/s²），kurtosis、skewness（1），vibration_impulse（g）；波形为s和m/s²，频谱为Hz和m/s²。

设备整机类别与监测部位分开：本案例整机为机械臂，监测部位为电机，采用电动机规则；可用case.json的point.diagnostic_category明确指定诊断类别。原台账不修改。

## 设备与数据范围

本节按三行四列展示：设备名称／安装区域、设备编码／监测部位、采集工况。台账字段分别来自device.device_name、device.region_name（未提供时使用device.location）、device.device_code、point.measure_point_name。设备编码与device.device_id平台ID分开，不互相替代；监测部位与component_raw、name_raw原始测点信息分开。新增字段缺失显示“未提供”，不推断。

采集工况由程序使用全部velocity_rms记录统计，单位须为mm/s：严格大于0.2为运行，小于等于0.2为停机。各占比=对应记录数/总记录数，以两位小数展示；两者合计100%。保留数据集、来源文件及运行/停机原始行号供核查。这是采集记录占比，不是设备运行时长占比；不从采样间隔推算时长，不作为机理规则前置条件。未提供速度记录时显示无法统计，不补造比例。

## 规则口径

加速度峭度等同峭度；通频速度有效值等同速度有效值。倍频频率=转速/60×阶次；该频率对应的频谱纵坐标就是本项目的倍频幅值或业务用语“能量”。能量和直接将指定纵坐标相加，不平方、不积分。

按用户指定，所有历史时刻重复使用当前这一份最新频谱坐标，与该时刻对应的特征值计算业务比值。输入单位保留，不隐式换算；该数值比值不称为无量纲物理能量比。这是共用最新频谱参考，不代表各历史时刻都采集过相应频谱，历史满足次数不应解释成独立频谱的重复验证。

历史指标按相同时间逐次对齐，使用全部记录，不只比较首末值，也不跨时刻组合不同条件。时间相同但ISO表示不同的记录规范化后对齐；不做最近值填补。分母非正、缺指标、缺转速或缺精确频谱坐标时，对应条件标为无法判定，其他条件继续。

当前将文档中电动机四类机理规则人工转为config/rules.json的结构化条件：轴承故障（三项）、转子不平衡（四项）、不对中（四项）、连接松动（两项）。区间上下界属于同一项。知识DOCX入口保持独立，上传不自动启用或提取执行规则；执行前匹配来源设备类别、故障名称和规则原文，来源变化明确提示，防止静默执行旧配置。

规则JSON支持单指标阈值、指标比值、指定倍频纵坐标之和与指标的比值。支持gt、gte、lt、lte。全部条件满足才判为对应故障，独立入口可编辑阈值及条件；只接受固定结构，不执行表达式代码。

## 结果

每个历史时刻分别列出满足、不满足、未知及总条件数。满足率=满足数/全部条件数，未知不计为满足，也不从分母排除。同一规则全部条件满足为故障；有明确不满足项则该规则正常；无不满足但有未知项时无法判定。不同规则独立判断，任一故障命中不被正常规则抵消。满足率仅供核查，不生成支持等级、概率或严重程度。当前与历史分别说明，详见 strict_matching_20261103.md。

每条规则分别展示最近结果、历史最高匹配、各条件满足次数、可完整判断次数和全部条件符合次数。全部条件符合率的分母为可完整判断次数；没有可完整判断记录时为null。不得将不同时间满足的条件拼成一次全部符合。

网页可展开全部时刻明细，rule_matches.csv导出全部条件的值、表达式、结果和原始来源。Word/PDF保留原模板字体，仅为当前或历史全部条件满足的故障方向配图并附机理含义；无故障方向的正常报告不插入无关图。完整逐次来源见CSV和依据JSON，正式报告不列规则明细表。

## 大模型与流程

collect → quality → prepare_evidence → rules → knowledge → write → render → validate → export。

程序完成全部规则计算并确定正常、故障或无法判定。模型接收每条件次数统计、最近与历史最高记录及来源和全部16条知识，只解释结果、提出建议，不自由增加故障，不要求补充工况。hypotheses固定空数组，程序结果在综合判定部分独立展示。write节点使用docs/report_writer_prompt.md，写作输入JSON同时保存实际系统提示词。

完整匹配明细保留服务器本地及下载文件；模型上下文提供明确约定的统计和代表记录，不静默截断。上下文超限停止，模型校验失败明确回退固定说明；程序匹配不受影响。当前仍为文本模型，未接入图片分析。
